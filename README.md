# ASIC Implementation Flow

This repository contains a complete, automated ASIC (Application-Specific Integrated Circuit) physical design and verification flow for the `neural_eq_top` design, utilizing industry-standard EDA tools.

## Overview

The repository is structured to take an RTL design through the entire backend flow, ultimately producing a Tape-Out ready GDSII layout. The flow encompasses Synthesis, Place and Route (PnR), Extraction, Static Timing Analysis (STA), Design for Test (DFT), and Formal Verification.

### Directory Structure

* **`syn/`**: Logic Synthesis using Synopsys Design Compiler. Converts RTL to a mapped gate-level netlist.
* **`pnr/`**: Physical Design using Synopsys IC Compiler II (ICC2). Includes standard stages:
  * Floorplanning
  * Power Planning
  * Placement
  * Clock Tree Synthesis (CTS)
  * Routing
  * Final Legalization and ECO
* **`qor/`**: Quality of Results Analysis & Signoff.
  * **`sta/`**: Static Timing Analysis using Synopsys PrimeTime.
  * **`rcxt/`**: Parasitic Extraction using Synopsys StarRC.
* **`dft/`**: Design for Testability insertions.
* **`formality/`**: Logic Equivalence Checking (LEC) using Synopsys Formality to ensure structural equivalence across synthesis and PnR stages.
* **`standard_cell_libraries/`**: Process Design Kit (PDK) and standard cell libraries (e.g., Nangate 45nm).

## The ECO Signoff Cycle

During the final signoff stages, the design undergoes an Engineering Change Order (ECO) cycle to resolve lingering setup, hold, and DRC violations. The loop typically operates as follows:

1. **Extract Parasitics**: Using StarRC (`qor/rcxt`).
2. **Run STA**: Using PrimeTime (`qor/sta/pt.tcl`).
3. **Calculate Fixes**: PrimeTime generates an ECO fix script (`write_changes -format icc2`).
4. **Apply ECO & Legalize**: Sourced back into ICC2 to resize, buffer, or move cells.
5. **Verify**: Loop back to extraction until all timing and physical metrics are clean.

## Note on Version Control

Due to the massive size of EDA tool databases, physical layouts, and extractions, the `.gitignore` is aggressively configured. It intentionally ignores:
- `standard_cell_libraries/` and `.ndm` databases.
- Layout binaries (`.gds`, `.def`).
- Heavy extraction binaries generated by StarRC (`star/` dirs).
- Extracted parasitics (`.spef`).
- Tool run logs, error files, and reports.
